# Preuves — quelle affirmation repose sur quelle mesure

Les mesures de ce projet sont dispersées dans les sections de `PLAN.md`, et un journal de run ne survit pas
au run suivant (`tools/run-session.sh` efface les journaux avant de lancer). Une affirmation peut donc
survivre à sa mesure. Cette page rassemble, **une ligne par affirmation**, l'instrument qui la soutient, le
fichier d'où viennent la ligne et la valeur, et son statut.

Règles de lecture :

- **instrument** : la ligne de journal, le fichier ou le compteur exact. Une affirmation sans instrument n'est
  pas dans la première partie — elle est dans « Non prouvé ou partiel ».
- **source** : le fichier (et, quand elle existe, la constante ou la section) où la ligne est produite ou
  citée. Aucune valeur de cette page n'est recopiée d'ailleurs.
- **statut** : `prouvé` (+ la date du run où la ligne a été relevée), `partiel`, ou `non prouvé`. Les runs
  cités sont ceux de `PLAN.md` ; ils ne sont pas rejouables à l'identique (journaux effacés).

Sauf mention contraire, un instrument vit dans `BepInEx/logs/coop-client.log` ou `coop-server.log` (et
`coop-client-<n>.log` pour un client supplémentaire, cf. `tools/run-session.sh --clients=N`).

## Ce que cette page ne prétend pas

- **Cette page n'est pas une suite de tests à elle seule.** Les instruments qu'elle cite s'exécutent dans
le jeu ; les **280 tests purs** de `tests/` couvrent le modèle (protocole, empreintes, bornes), mais **pas** la
couleur, l'objet tenu ni l'animation (cf. `docs/authority.md` §3). Un `prouvé` ici veut dire « une ligne de
journal a été relevée une fois », pas « rejoué à chaque run ».
- **Ce qui se rapproche d'une suite, c'est `tools/verify.sh`** : il rejoue **vingt-et-une** runs (avatar +
créatures ; deux clients avec la sonde de présence — équipement, `PlayerId` falsifié, outil tenu, nage ;
plafond abaissé ; autotest de la garde de sauvegarde ; créatures seules à deux clients ; sauvegarde de
l'hôte ; Seamoth en mouvement ; serveur dédié sans personnage ; menu Échap du client sans gel ; diffusion et
interpolation du véhicule ; les **deux** runs de la clé nominale — préparation puis mesure ; le ramassage
d'un objet réel, clé falsifiée, geste bloqué et objet retiré chez l'autre ; la conduite arbitrée à deux
clients, **libération et reprise** ; la création d'entité et son rejeu à un client tardif ; la disparition
d'un véhicule chez les deux clients ; la position autoritaire et l'empreinte de sauvegarde — nage normale
non corrigée, téléport refusé et appliqué ; le rejeu d'un retrait à un client arrivé après coup) dans une
seule commande, affirme les lignes attendues et rend un verdict unique. **Les vingt-et-une étapes ont un verdict
vert au 2026-10-20** (`PLAN.md` §46, §47.3 et §49.5) ; P et Q ont été rejouées seules après les correctifs du
modèle, R après le tri déterministe des slots, et S/T/U le 2026-10-20 (`PLAN.md` §52).
Une affirmation de cette page marquée `prouvé` et couverte par l'une de ses étapes est donc rejouable —
les autres (marche, zones et sauvegardes différentes, plus de 8 joueurs) ne le sont pas encore.
- **Un compteur absent n'est pas une preuve d'absence.** Chaque ligne doit être lue avec son périmètre : par
  exemple `clés partagées=0` porte sur 100 clés d'un monde et d'une zone, pas sur toutes les créatures du jeu.
- **Les valeurs ne sont pas recopiées de mémoire** : chacune vient d'une section de `PLAN.md` ou d'un fichier
  nommé dans la colonne « source ». Si une ligne de cette page contredit le code, c'est le code qui a
  raison — et la page doit être corrigée.
